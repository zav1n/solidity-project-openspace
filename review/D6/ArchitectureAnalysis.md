# DeFi项目架构分析模板

## 1. 合约依赖关系图

### 1.1 核心合约关系

```
+---------------------+      +----------------------+
|                     |      |                      |
|  管理/治理合约      +----->+       核心业务逻辑合约    +-----+
|                     |      |                      |     |
+---------------------+      +----------------------+     |
                                                          |
+---------------------+      +----------------------+     |
|                     |      |                      |     |
|  外部接口/路由      +----->+      辅助/工具合约       |     |
|                     |      |                      |     |
+---------------------+      +----------------------+     |
                                                          v
                              +----------------------+
                              |                      |
                              |  数据存储/状态合约      |
                              |                      |
                              +----------------------+
```

### 1.2 合约交互流程

1. **用户入口**：用户通常通过路由合约或外部接口与协议交互
2. **业务处理**：核心业务逻辑合约处理主要功能
3. **状态更新**：数据存储合约维护协议状态
4. **辅助功能**：工具合约提供计算、验证等辅助功能
5. **治理控制**：管理合约控制协议参数和升级

## 2. 状态变量追踪

### 2.1 关键状态变量表

| 合约名称 | 变量名称 | 数据类型 | 访问权限 | 用途描述 | 修改函数 | 读取函数 |
|---------|---------|---------|---------|---------|---------|----------|
| TokenPool | reserves | mapping(address => uint256) | private | 记录每种代币的储备量 | deposit(), withdraw() | getReserve() |
| LendingPool | userCollateral | mapping(address => mapping(address => uint256)) | private | 记录用户抵押品 | supplyCollateral(), withdrawCollateral() | getUserCollateral() |
| PriceOracle | assetPrices | mapping(address => uint256) | private | 记录资产价格 | updatePrice() | getAssetPrice() |

### 2.2 状态变更流程

```
用户操作 --> 前置检查 --> 状态更新 --> 事件发射 --> 后置操作
```

#### 示例：存款流程中的状态变更

1. **前置检查**：验证输入参数、暂停状态、用户余额
2. **状态更新**：
   - 更新用户余额映射
   - 更新协议总储备量
   - 计算并分配利息
3. **事件发射**：触发Deposit事件
4. **后置操作**：更新利率模型参数

## 3. 事件分析

### 3.1 关键事件列表

| 事件名称 | 参数 | 触发条件 | 用途 |
|---------|------|---------|------|
| Deposit | asset, user, amount, timestamp | 用户存款成功 | 记录存款操作，用于前端显示和数据分析 |
| Borrow | asset, user, amount, interestRate | 用户借款成功 | 记录借款操作，用于风险监控 |
| LiquidationCall | collateralAsset, debtAsset, user, liquidator, amount | 清算操作执行 | 记录清算事件，用于市场监控 |

### 3.2 事件追踪示例

通过追踪`LiquidationCall`事件，可以分析：

- 清算频率和规模
- 最常被清算的资产类型
- 市场波动与清算关系
- 清算人行为模式

## 4. 安全机制

### 4.1 权限控制

| 功能 | 控制方式 | 权限角色 | 实现方法 |
|------|---------|---------|----------|
| 协议参数更新 | 角色访问控制 | 管理员 | AccessControl或Ownable模式 |
| 紧急暂停 | 暂停机制 | 守护者 | Pausable模式 |
| 合约升级 | 代理模式 | 治理 | 透明代理或UUPS模式 |

### 4.2 风险控制

- **价格预言机安全**：多重预言机、心跳检查、偏差阈值
- **流动性风险**：借贷上限、利率模型、储备因子
- **清算机制**：健康因子、清算阈值、清算奖励
- **重入防护**：ReentrancyGuard、检查-效果-交互模式

## 5. 架构优势与风险

### 5.1 架构优势

- **模块化设计**：各组件职责明确，便于升级和维护
- **可扩展性**：新资产或功能可以轻松集成
- **安全性**：多层次安全机制，风险隔离

### 5.2 潜在风险

- **合约间依赖复杂性**：组件间紧密耦合可能导致连锁反应
- **升级风险**：代理模式升级可能引入新漏洞
- **治理风险**：权限过度集中可能导致单点故障

## 6. 架构改进建议

- **增强模块化**：进一步分离核心逻辑和辅助功能
- **简化用户流程**：减少交互步骤，优化用户体验
- **增强风险隔离**：引入多层次风险参数和限制
- **优化gas效率**：重构高频调用函数，减少存储操作

## 7. 分析工具与方法

- **静态分析**：Slither, Mythril等工具检查代码安全性
- **形式化验证**：使用Certora等工具验证关键属性
- **经济模型模拟**：Agent-based模拟测试不同市场条件
- **链上数据分析**：使用Dune Analytics等工具分析协议使用情况
