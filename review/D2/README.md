## ERC标准面试题
### 理论题
1. 问题 ：解释ERC-20和ERC-721标准的主要区别，并说明各自适用的场景。
ERC-20 是同质化代币标准，适用于可互换的资产；而 ERC-721 是非同质化代币标准，适用于独特的、不可替代的数字资产。
ERC20适用于: 稳定币, 流动性代币, 投票权和治理代币
ERC721适用于: NFT, 虚拟土地和房产, 身份证明和证书

2. 问题 ：ERC-20标准中的 approve 和 transferFrom 函数有什么作用？它们如何协同工作？
approve: 授权第三方可调用自身特定数量的代币
transferFrom: 允许已获授权的地址转移代币

3. 问题 ：在实现ERC-721合约时， tokenURI 函数的作用是什么？如何正确实现元数据标准？

4. 问题 ：解释ERC-1155与ERC-721相比有哪些优势？什么场景下应该选择ERC-1155而非ERC-721？
管理多种类型代币时选择1155: 可转移多种不同类型的代币, gas成本低, 同一合约可同时支持可替代和非可替代代币

空投, 批量铸造和分发, 游戏中的道具, 大规模NFT项目, 混合经济, 可替代性可变的资产

## Web3.js/ethers.js前端交互面试题
### 理论题
1. 问题 ：比较Web3.js和ethers.js的主要区别和各自优势。
web3js 作为早期的js库功能会更全面
wthwejs 体积小, 实现了读写分离, 适合大量以太坊交互功能

2. 问题 ：解释在前端应用中如何安全地处理用户的私钥和签名请求。
- 即用即丢不在前端存储
- 使用web3modal或walletConnect处理私钥
- 使用EIP712对交易进行签名, 签名请求中展示域名和应用名称防止钓鱼, 添加时间戳和nonce防止重入攻击

3. 问题 ：当监听合约事件时，如何处理网络重组(reorg)可能带来的问题？
网络重组是指区块链分叉后，较短的链被丢弃，交易被重新排序的情况。这可能导致：
- 已确认的交易被回滚
- 事件顺序改变
- 某些事件消失或新事件出现
解决方法是: 
1. 等待最新交易的执行, 或者是根据区块高度;如果遇到交易卡住, 可以使用nonce进行替换失败的交易
2. 实现事件重放机制，使用唯一标识符（transactionHash+logIndex）


4. 问题 ：解释gas估算的重要性，以及在前端如何实现动态gas估算。
- estimateGas函数预估gas
- 准确的gas估算可以避免交易失败, 交易失败gas不会回退
- 防止用户支付过高的gas费用
- 网络拥堵时，动态调整gas可以节省费用
